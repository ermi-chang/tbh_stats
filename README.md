## UI Refactor Guide

UI を先に触るときは、`src/tbh_ocr_stats/app.py` を見た目専用のファイルだと思わない方が安全です。まだ 1 ファイルに UI、OCR 呼び出し、セッション状態管理、DB 書き込みが残っていますが、実行環境依存は次のモジュールへ分離し始めています。

- `src/tbh_ocr_stats/runtime_env.py`
  実行フォルダ、`config.json`、`data/`、`exports/`、DB 接続、同梱 Tesseract 解決を担当します。
- `src/tbh_ocr_stats/ocr_core.py`
  OCR 前処理、金額 OCR、ステージ OCR、ゲージ判定などの純ロジック置き場です。
- `src/tbh_ocr_stats/anchor_core.py`
  anchor 検出、boss 検出、自動 ROI 計算のロジック置き場です。

比較的安全に触りやすい場所:

- `_build_ui()` と各 `_build_*_tab()`
- `_apply_theme()`
- `apply_ui_language()`
- ラベル文言、スタイル、レイアウト調整

UI 改修時に挙動を壊しやすい場所:

- `begin_stage_run()`
- `finish_stage_run()`
- `on_gauge_finished()`
- `commit_stage_from_finish_ocr()`
- `start_session()`
- `stop_session()`
- `on_worker_finished()`

上の関数は、表示更新だけでなく次も一緒に持っています。

- セッション開始・停止
- OCR タイマー
- ステージ境界判定
- DB 保存
- ハイスコア更新

先に読むと流れを追いやすい helper:

- `_refresh_stage_views()`
- `_set_stage_wait_start()`
- `_set_stage_running()`
- `_set_stage_finish_pending()`
- `_set_stage_finishing()`
- `_begin_session_runtime()`
- `_persist_session_start()`
- `_persist_session_stop()`
- `_apply_money_result()`
- `_persist_worker_sample()`
- `_handle_worker_purpose()`
- `_show_worker_debug()`

UI 改修前のチェック:

1. `py_compile` が通ること
2. `範囲・OCR` タブの preview と `OCRテスト` が動くこと
3. `計測開始 -> 1ステージ記録 -> 停止` の最小スモークが通ること
4. `build_release.bat` と `verify_release.bat` が通ること
